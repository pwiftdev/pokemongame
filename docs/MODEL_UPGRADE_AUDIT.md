# Model upgrade audit

Reviewed the model loader, actor animation selection, environment assembly, camera filtering, asset acquisition, and manifest after integrating the authored models.

- Reuse: creatures, trainers, and scenery use one model library. Existing terrain heights, path layout, encounter positions, collision proxies, labels, quality settings, and shadow cleanup are reused. Extracted terrain and scenery assembly into separate helpers; removed the procedural trainer and primitive scenery builders.
- Unused code/imports: TypeScript passes with `--noUnusedLocals --noUnusedParameters`. Removed unused wall and roof models and the superseded creature directory. Manifest checks reject unlisted or missing runtime files. Palette colors no longer allocate unused materials.
- Performance: scenery instances share geometry/materials; player and creature clones retain separate skeletons and visibility. Texture files are shared and capped at 512 pixels. Low quality reduces plant density. Small decorative plants do not enter shadow or camera raycast lists.
- Error handling: all model loads settle before startup cleanup, including successes that arrive after a failure. Failed model downloads block entry and recover after reload. Unknown model names raise explicit errors. Missing animation support is caught by both file inspection and actual browser playback tests.
- Security: runtime asset paths are fixed local constants. No user-provided URLs, new endpoints, database changes, remote runtime hotlinks, or new package dependencies. Acquisitions are documented and checksum-verified; downloaded HTML is stored only under the source archive.
- Gameplay: cottage walls fit the existing authoritative obstacle radii. Decorative props remain scenery, consistent with the existing architecture. Trainer/companion mesh fading and camera raycasts operate on imported geometry; critical gameplay effects are retained.
- Limits: the higher detail assets increase download size and geometry counts. A short local Chromium check reached approximately 60 FPS at 1440×900; this is not a claim about mobile hardware, 16 rendered players, or long-session memory usage. Animation crossfades, custom terrain textures, and bespoke creature identity art remain future visual work.

Validation completed: 41 unit tests and all nine Playwright browser tests passed, including two independent browser players completing a duel. TypeScript (including unused code checks), production build, asset checksums, and Prettier passed. The build retains Babylon's large-bundle warning. Final meadow/forest traversal produced no page errors and approximately 59 FPS at 1440×900; see `evidence/models-review.json` and `evidence/models-meadow.png` / `evidence/models-forest.png`. The packaged asset inventory is 60 models plus 42 shared textures, totaling 23,839,496 bytes before HTTP compression.
